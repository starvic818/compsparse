## 0. 一页速览

**研究问题**：在视频 DiT 的全时自注意力中，用"精确计算 + 一阶泰勒补偿"替代"保留/丢弃"的二分策略，
能否在长序列（N ≥ 3×10⁴）上把被近似注意力质量的误差从 O(ρ) 降到 O(ρ·Δ²)，
从而在拿到 kernel 层 4~5x 加速的同时，把背景闪烁压回 baseline 水平？

**当前状态**：无卡期的可完成项已全部完成（推导、参考实现、可行性分析、评测套件、执行脚本、
硬件裁剪、任务书）。**只剩两件事必须等卡**：① 真实 logits 分布（决定补偿有没有用武之地）；
② 端到端加速比与配对质量指标。

**关键数字**（全部可复算）：

```text
序列长度  480p/81f: N=32760   720p/81f: N=75600   480p/161f: N=63960
注意力占比  480p: 73%   720p: 86%          -> 端到端上限 1/((1-A)+A/S)
补偿开销  (1+ρ)d/(2N) = 480p 0.35% / 720p 0.15% / N=4096 2.8%
端到端上限  ρ=0.8: 纯硬丢弃 2.40x，一阶补偿 2.39x（补偿只损失约 0.4%）
一阶/丢弃 break-even: |delta| = 1（此时 1+delta = 0）
误差界   ε(Δ)=(Δ²/2)e^Δ  ->  Δ=0.27 时 5%，0.37 时 10%，0.49 时 20%
补偿有效区间（合成标定）: logit std ≲ 0.35；std=0.056 时收益 373x，std=0.674 时收益 1.0x
实验预算  16 prompt × 2 seed × 3 方法 = 96 条 ≈ 7.4 GPU-小时（480p / 50 步）
```

## 2. 方法要点（结论版）

**① 精确拆分（恒等式）**：`o_i = (1-ρ_i)·o_i^S + ρ_i·o_i^C`，ρ_i 是该行被近似的质量比例。
硬丢弃偏差严格正比于 ρ_i，而 ρ_i 逐行可测。

**② 三段划分**（这是对 v1 的重要修正）：

```text
A（补偿，近端）:  |delta| <= Δ_1        —— 一阶泰勒在这里最准（delta=0 处精确）
E（精确，中段）:  Δ_1 < |delta| < Δ_2    —— 一阶已不准、质量又不可忽略
D（丢弃，远端）:  |delta| >= Δ_2         —— 质量已可忽略
```

v1 的错误：把"可安全丢弃"的判据写成用 **Δ_max**（最深）。正确的关系是
**补偿看 Δ_max（最深）、丢弃看 Δ_min（最浅，尾部上边缘）**，两者方向相反。

**③ 阈值来源**：`Δ_1` 由 `ε(Δ_1)=(Δ_1²/2)e^{Δ_1} ≤ τ` 反解；`Δ_2` 由尾部质量 ≤ ε_tol·z 反解。
硬下界提醒：|δ|>1 时一阶近似比直接丢弃更差（1+δ 变号，实测 break-even = 1）。

**④ 补偿几乎免费**：`补偿开销/稠密注意力 ≈ (1+ρ)d/(2N)`，480p 下 0.35%；
折算端到端上限：纯丢弃 2.40x，一阶补偿 2.39x。

**⑤ 反直觉推论（H4）**：既然一阶在 δ≈0 处精确，**注意力质量最大的 key 恰恰是补偿最准的地方**，
把精确预算全花在最高 logit 上是浪费。合成数据上"中段精确"在 std≈0.2–0.4 区间误差低 2–4 倍。

**⑥ 误差代理已标定**（真实规模算不出精确误差，只能用 logits 代理）：
补偿主导区间 `bound_worst/actual = 0.71~1.24`（可直接用）；丢弃主导区间 `0.32~0.65`（偏乐观，
输出里带 `optimistic` 标志）。RMS 型代理低估 10 倍，已弃用。

## 3. 实验设计

**固定项（变了就不能配对）**

```text
模型: Wan2.1-T2V-1.3B @ 固定 commit        （14B 出局：bf16 权重 28GB > 24GB 显存）
prompt: 16 条 × 4 类（high_motion / low_motion / complex_texture / static_background）
seed: 每条 prompt 固定 2 个，跨方法复用（同一 seed 才能配对）
采样: 定稿 50 步 UniPC, shift=8, CFG=6, 81 帧；迭代期降到 16–20 步
硬件: 单卡 RTX40 系 24GB；测速时 offload_model=False（DiT 仅 2.7GB）
计时: CUDA events，只统计采样循环，排除模型加载与文本编码；≥3 次取中位数
```

**自变量（按优先级）**

```text
① 策略: 硬丢弃(order-0) / 一阶补偿(order-1) / 混合阶(分子一阶+分母二阶) / dense
② 稀疏率: 0.5 / 0.7 / 0.8 / 0.9
③ 序列长度（主轴）: 480p-81f(N=32.8k) / 480p-161f(N=64k) / 720p-81f(N=75.6k，仅单点确认)
④ 分块粒度与时间跨度（控制 Δ 的分布）
⑤ 精确预算的分配方式（top-m vs 中段，对应 H4）
```

**因变量**

```text
效率: 端到端 latency / peak memory / kernel 层 attention 耗时 / 选择开销占比
机理: 逐层逐头 rho、delta 直方图、层内输出相对误差、背景功率谱低频占比
质量: flicker_index、bg_l1、warp_resid、patch_dc_var / VBench 三件套 / （补充）相对 FVD
```

**时间与成本**

```text
一轮 pilot（4 策略 × 4 稀疏率 × 4 prompt × 1 seed, 480p）≈ 64 条 ≈ 5 GPU-小时
完整矩阵（96 条 + 720p 单点）≈ 8~10 GPU-小时
省时要点: 一次加载跑完（sweep.py）、迭代期 16–20 步、断点续跑
```
