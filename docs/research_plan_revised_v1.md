## 0. 研究问题与假设

**一句话研究问题**：在视频 DiT 的全时自注意力中，用"精确计算 + 泰勒补偿"替代"保留/丢弃"的二分策略，
能否在长序列（N ≥ 3×10⁴）上把被丢弃注意力质量的误差从 O(ρ) 降到 O(ρ·Δ²)，从而在拿到
kernel 层 4~5x 加速的同时，把背景闪烁压回 baseline 水平？

> 硬件边界（Compshare 单卡 RTX40 系 24GB）单独写在 `hardware_scope_rtx40_24g.md`：
> 模型锁定 1.3B、FA3 不可用、长序列主轴改用 480p/161f。实验矩阵以那份文档为准。

三条可证伪假设（每一条都给出证伪条件）：

| 编号 | 假设 | 证伪条件 | 对应实验/指标 |
|---|---|---|---|
| H1 | 在该配置下自注意力占总 FLOPs ≥ 70%，因此仅优化注意力仍有 2x 级端到端空间 | profiler 实测占比 < 55% | 第 1 周 profile |
| H2 | 一阶补偿把近似集输出误差从 ρ 量级降到 ρ·ε(Δ)，Δ ≤ 0.3 时中位相对误差 < 2% | 实测相对误差随 Δ 下降缓慢或高于理论界 | 实验 V1（层内微基准） |
| H3 | 背景闪烁主要来自硬丢弃的 ρ 偏差项，因此 flicker 与 mean(ρ) 近似线性，且补偿后显著下降 | flicker 与 ρ 无线性关系，或补偿后台闪烁无改善 | 实验 V2/V3/V4 |

**如果 H2 或 H3 被证伪，项目依然成立**：证伪本身就是结论（说明误差主导项在分母一致性、
索引粒度或跨层累积，而不是截断阶数）。这是把"移植工程"变成"研究"的关键——请把证伪路径也写进报告。

## 1. 原表述 → 可检验形式

| 原方案表述 | 问题 | 改写为可检验形式 |
|---|---|---|
| "实现 1.5x–2.5x 端到端加速" | 未说明上限来自哪里 | 先测 attention 占比 A，得到上限 1/((1-A)+A/S)；目标写成分层指标（kernel 层 S、端到端 E） |
| "PISA 补偿项消除背景闪烁" | 未量化闪烁，且未验证补偿项存在 | 用 flicker_index（相对配对 baseline）量化；先按推导文档第 9 节核对补偿项是否真实存在 |
| "用 FVD 评估连贯性" | FVD 是分布距离，对局部闪烁不敏感，且 n<64 时方差极大 | 主指标换成 VBench 三件套 + 配对闪烁指标；FVD 仅作"整体未崩"的补充 |
| "对比不同稀疏率下 FPS 提升" | 单一自变量，无法解释机理 | 自变量扩为：稀疏率 × 分块粒度（Δ 的代理）× 分辨率/帧数；因变量含 ρ_i 分布 |
| "消融补偿项的贡献" | 若无补偿项或未控制其他变量则无意义 | 三组对照：硬丢弃 / 一阶补偿 / 精确（同稀疏率、同 seed），配对检验 + ρ×策略交互 |

## 2. 实验设计

**固定（绝不能变，变了就不能配对）**

```text
模型: Wan2.1-T2V-1.3B @ 固定 commit
prompt 集合: 16 条，覆盖 high_motion / low_motion / complex_texture / static_background 四类
seed: 每条 prompt 固定 2 个 seed（同一 seed 跨方法复用）
采样: 定稿数字用 50 步 UniPC, shift=8, CFG=6, 81 帧；迭代期降到 16–20 步
硬件: 同一张卡、同一镜像；测速时 offload_model=False（若显存不足则 True/False 各报一组）
计时: 不计模型加载与文本编码；用 CUDA events + warmup + 3 次重复取中位数
```

**自变量矩阵（按优先级，预算不够就先做①②）**

```text
① 策略:        硬丢弃(order-0) / 一阶补偿(order-1) / 混合阶(分子一阶+分母二阶) / dense 基线
② 稀疏率:      0.5 / 0.7 / 0.8 / 0.9
③ 分辨率/帧数: 480p-81f / 720p-81f / 480p-161f      <- 主轴是序列长度，不是分辨率
④ 分块粒度:    时间窗 {1, 2, 4} 帧（用来控制 Δ 的分布）
```

**因变量**

```text
效率: 端到端 latency / peak memory / kernel 层 attention 耗时
机理: 逐层 ρ_i 分布、Δ_i 分布、层内输出相对误差
质量: flicker_index、bg_l1、warp_resid、patch_dc_var、VBench 三件套、（可选）相对 FVD
```

**成本核算（按你实测 5.2 s/it、50 步 ≈ 4.5 分钟/条 480p）**

```text
一轮 pilot (4 策略 × 4 稀疏率 × 4 prompt × 1 seed, 480p) ≈ 64 条 ≈ 5 GPU-小时
完整矩阵 (加 720p 与 161 帧, 720p 约 3~4x 慢)            ≈ 30~40 GPU-小时
省时要点: 一次加载模型跑完所有配置（当前每条命令浪费约 2 分钟加载）
          迭代期用 16–20 步（省 60%），只有定稿数字回 50 步
```

## 4. 七周重排

### 第 1 周：让地基可信（不做任何算法改动）

```text
任务
  1. 修视频落盘：确认 baseline 视频真实存在、可解码、帧数 81（当前日志里有 cache_video failed）
  2. 锁参数：seed / 步数 / solver / shift / CFG / offload 全部固定并写进 manifest
  3. 分组件计时：T5、采样循环、VAE 解码；采样内再拆 self-attn / cross-attn / FFN / rope
  4. 记录 peak memory（torch.cuda.max_memory_allocated）
  5. 逐条填完推导文档第 9 节的机制核对清单
产出: D1, D2, D3
go/no-go: 实测 attention 占比 A。若 A < 55%，把主战场移到 720p/161 帧（否则端到端上限 <1.8x）
```

### 第 2–3 周：算法原型 + 层内验证（先 PyTorch，不写 kernel）

```text
任务
  1. 用 mask + 矩聚合实现三个变体：order-0 / order-1 / hybrid（分子一阶 + 分母二阶）
     关键点：分子分母同阶、c_i 取整行 max、sink/首帧强制精确、RoPE 在矩聚合前施加
  2. 实验 V1：抓真实 q/k/v，扫 Δ，画 rel_err 与理论界 ε(Δ)=(Δ²/2)e^Δ
  3. 实验 V2：统计 ρ_i 的空间分布（背景 vs 前景），检验 P1
产出: D4, D5
go/no-go: Δ ≤ 0.3 时中位相对误差 < 2%。若远高于此，先怀疑实现（分母不一致/RoPE 顺序/max 稳定化），
          而不是怀疑理论——因为命题 1 的不等式是无条件成立的
```

### 第 4–5 周：接进 Wan2.1 + 端到端实验

```text
任务
  1. 替换 WanSelfAttention 的注意力调用（monkey-patch 或改 forward），cross-attention 不动
  2. 先跑 480p-81f 的 4 策略 × 4 稀疏率 pilot，确认趋势后再扩到 720p / 161 帧
  3. 用 video_quality_eval 跑配对指标；正式数字补 VBench 三件套；样本够（≥32）再补相对 FVD
  4. 检验 P2（flicker vs ρ 线性）、P3（ρ×策略交互）、P4（低频能量占比）
  5. 确认算法有效后，再决定是否做 Triton/FlexAttention kernel 化
产出: D6, D7, D8
go/no-go: 端到端加速 ≥ 1.2x 且 flicker_index ≤ 1.05（相对 baseline）。
          若加速不足，先看 ρ 与 kernel 层 S 是否达到设计值，再决定是否进入 kernel 化
```

## 5. 风险与降级路径

| 风险 | 触发信号 | 降级动作 |
|---|---|---|
| attention 占比低，端到端上限不够 | profile 显示 A < 55% | 主战场移到 720p / 161 帧；把"长序列 scaling"作为主结论 |
| kernel 化失败（时间不够/写不出快 kernel） | 第 3 周末仍无可用的 Triton 实现 | 用 PyTorch mask 版 + 层内 micro-benchmark 报"理论加速比 + 单层实测"，端到端只报趋势；报告里明确说明限制 |
| 补偿项与假设不符（原文机制不是泰勒补偿） | 核对清单中出现"不是" | 转为"机制分析 + 评测"型报告：比较硬丢弃与原文策略在视频域的表现差异 |
| 质量指标噪声大（CI 跨 0） | paired_summary 大量 no_significant_difference | 增加配对样本；改用 static_background prompt 子集（信噪比更高）；报告 CI 宽度而不是点估计 |
| 显存/时间超预算 | 单次 720p 生成 > 20 分钟 | 降到 1.3B + 480p 做主线，720p 只做少量验证点 |
| 端到端只有 1.2–1.6x | 达不到 2.5x | 把目标改成分层：kernel 层 3~5x、端到端 1.2–1.6x，并用公式 1/((1-A)+A/S) 解释差距 |

## 6. 答辩预演（评审一定会问）

```text
Q1 你的"补偿项"到底减少了什么误差？请写出公式。
   A: 硬丢弃误差 ≈ ρ_i；一阶补偿误差 ≲ ρ_i·(Δ²/2)e^Δ。给出 ρ 与 Δ 的实测量。
Q2 为什么背景比前景更容易闪？
   A: 背景 token 的注意力分布更平坦，ρ_i 更大（用 V2 的 ρ 分布图回答）。
Q3 稀疏率 0.8 省了 80% 的注意力 FLOPs，为什么端到端只有 1.6x？
   A: Amdahl：1/((1-A)+A/S)，A 是实测 attention 占比，S 是 kernel 层加速比；再扣除选择开销与 CFG。
Q4 你怎么证明"闪烁"改善了？FVD 不行吗？
   A: FVD 是分布距离，对局部时序不稳不敏感；我们用配对 flicker_index + VBench background consistency 交叉验证。
Q5 相比 Sparse VideoGen / MInference 这类工作，你的增量是什么？
   A: 明确写出 1–2 条（时空分块受 RoPE 时间跨度约束的 Δ 界；补偿开销的闭式 (1+ρ)d/(2N) 及其适用区间）。
Q6 稀疏选择（top-k/分块打分）本身的开销是多少？会不会吃掉收益？
   A: 给出实测的选择耗时占比，并与 (1+ρ)d/(2N) 的补偿开销对比。
Q7 你的 Δ 阈值怎么定的？
   A: 由 ε(Δ)=(Δ²/2)e^Δ ≤ τ 反解，而非照搬论文；给出 τ=5/10/20% 对应的 0.27/0.37/0.49。
Q8 为什么 720p 的加速比比 480p 好？
   A: N² 增长使 attention 占比从 73% 升到 86%，且补偿开销 ∝ 1/N 下降。
Q9 如果你的假设不成立呢？
   A: 说明证伪条件与备选解释（分母一致性/索引粒度/跨层累积），并给出已有证据。
```

## 7. 与上一版方案的差异

```text
1. 顺序: 原方案把"环境+基准"（第1周）后直接进入"移植实现"（第2-3周）。
   现在第 2-3 周先做"层内微基准 + 机制推导"，因为它决定后面所有实验的意义；
   算法接进模型推迟到第 4 周，此时你已知道补偿项是否真的存在、误差界是否成立。
2. 指标: FVD 从主指标降为补充指标，主指标换成配对闪烁指标 + VBench 三件套。
3. 自变量: 增加"分块粒度/时间跨度"（Δ 的直接控制变量），序列长度成为实验主轴。
4. 判据: 每个阶段给出 go/no-go 数值，避免"跑到第七周才发现端到端只能 1.2x"。
5. 目标: 从单一的"1.5–2.5x"改成分层目标（kernel 层 S、端到端 E、质量损失上限），
   并给出 Amdahl 上限公式解释二者差距。
6. 交付: 增加 D2/D3/D4/D5 四个"机理类"交付物，让报告不止有曲线，还有可验证的机制。
```
